# Verified CI job retry (optional)

`op-agent-engine-ci-retry` is an engine reconciliation command, not a model, an OpenProject principal or a workflow dispatcher. Schedule it on a timer in an isolated service identity. It needs no OpenProject account, shell from a task, or model permission change. Existing `run`/`once` deployments remain unchanged. Never pass the Actions-write credential to the role worker process tree. The helper can reconcile even if the original work package is held; it does not change review or ticket state. The normal engine can consume the provider's resulting checks. A retry is **not** an approval.

The independent resource owner periodically handles recoverable incidents and publishes a batch of trusted records. The coordinator accepts local private read-only `--inbox DIR` or a JSON array on `--receipts-stdin` **only from an authenticated source**. A record has `version: 1`, `repo`, `workflow` (filename), `runner`, and offset-aware `since`, `until`, `ready_at` timestamps. `since..until` bounds the old incident; `ready_at` attests actual health, not intent. Stale receipts (over 24 hours), future or inverted intervals do not qualify. This is not an HTTP endpoint. Do not consume PR comments, patches, artifacts, agent worktrees or arbitrary user-supplied receipts. Directory and all ancestors/config/transport must not be writable by agent identities. Keep the SQLite DB persistent and exclusive to the coordinator; deleting/restoring old DB state can lose the retry budget.

Policy is a deployment-owned JSON object: `repo`, `workflow`, reviewed workflow git `workflow_blob`, `base`, `runners`, target `job`, failing `step`, exact `diagnostic` line (`{runner}` substitution), `checkout_job`, `checkout_step`, a permitted `dependent_verdict` job, and `required_success` sibling jobs including checkout. The checkout step must report a timestamped exact merge SHA. Changing the workflow blob requires new policy review. A job whose failure cannot be attributed to a specific incident is ineligible.

Use a repo-scoped token supplied as the file `actions-token` in `CREDENTIALS_DIRECTORY`, with Actions/contents/PR **read** for observation. A later reviewed rollout can give only the isolated coordinator Actions write. Run `op-agent-engine-ci-retry --policy /etc/ci/policy.json --inbox /var/lib/ci/receipts --db /var/lib/ci-coordinator/retries.sqlite`. Without `--apply` it cannot POST or spend a budget. Compare observed outcomes with genuine terminal provider results before enabling `--apply`. No engine permission to synthesize a push, modify checks, dispatch a workflow, or bypass required reviews is needed. Inspect the service journal for decisions and the `retries` table for claims. Credentials and raw workflow logs are not written there.

Only a failed, completed first PR attempt, on the current same-repo head/base and exact tested merge commit, with the approved failure, required successful siblings, and no competing/newer workflow run at the head can qualify. The mutation is GitHub's individual job-rerun endpoint (GitHub also reruns its dependent verdict). Never retry application failures, incomplete provider data, manual builds, later attempts or unrelated jobs. The coordinator commits a unique SQLite claim before the single POST and checks eligibility again. Two collectors cannot spend the budget twice. A lost response/crash leaves a durable claim; polling later attempts reconciles it **without re-submission**. If the provider never confirms it, leave it unresolved rather than buying liveness with a duplicate. GitHub has no compare-and-retry transaction; if a push races after the final lookup, any accepted retry is still bound to the old job and must not qualify the new revision.

Rollout: observe → synthetic concurrency/crash tests → privately inspect a real observe decision → explicit opt-in. Disable the timer or remove `--apply` to roll back without deleting claims. Partial/oversized API listings or unavailable provenance fail closed; this pilot isn't a general-purpose scheduler. It doesn't automatically resume held OpenProject tickets or repair infrastructure itself.
